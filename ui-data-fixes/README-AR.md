# إصلاحات التنبيهات وفترة المطر والاتصال — ١٩ أكتوبر ٢٠٢٦

معاينة مستقلة: https://hada-ui-data-fixes-preview.humairi855.workers.dev/

الفرع: `redesign-hada-2026-10`. لا نشر على hada-weather.com، ولا تغيير main أو راصد هدى أو Neon أو خدمة الإشعارات. مصدر البداية ملفات الواجهة العامة التي فُحصت في تقرير `reviews/2026-10-19`؛ ليست إعادة بناء للموقع. المصدر الخلفي للإنتاج لم يُنسخ أو يُستبدل، ولا تُستخدم الحزمة القديمة لنشر هذا التغيير.

## ما تغيّر

- صياغة حالة التنبيهات الهادئة: «لا توجد تنبيهات جوية نشطة حاليًا». لم تتغير شروط التحذير أو مصادره.
- بطاقة المطر تختار أعلى احتمال ساعي ضمن الفترات التي لم تنتهِ، وتحتفظ بالساعة الجارية حتى نهايتها. تعادل النسب يرجّح الفترة الأقرب.
- تعرض التاريخ الكامل وبداية ونهاية الفترة بنظام ١٢ ساعة، وكمية المطر للساعة إن توفرت. توضح أن كمية الساعة الجارية تشمل الجزء الذي مضى، ولا تستبدل القيمة المفقودة بصفر.
- يعاد تقييم الفترة كل دقيقة دون طلب جديد، لتخرج الفترة عند انتهائها. لا عرض لذروة منتهية.
- عند فشل الاتصال: إعادة المحاولة بعد ١٠ ثوانٍ ثم ٣٠ ثم ٦٠ ثم كل ٥ دقائق، مع زر إعادة محاولة ومنع تكرار الطلبات المتزامنة. التحديث المعتاد بعد النجاح يبقى كل ١٥ دقيقة.
- لا تُعرض بيانات محفوظة بعد ٤٥ دقيقة أو بعد تغير اليوم المحلي. تُمسح أيضًا ملخصات تبويبات التوقع والرياح حتى لا تعيد إظهار بيانات قديمة.
- تحسين قراءة تاريخ الفترة داخل بطاقة المطر على المقاسات الصغيرة؛ التنسيق مقيّد ببطاقة المطر وحدها.

لم تُطبّق رقعة التنظيف السابقة ضمن هذه المرحلة؛ بقيت تغييرات هذه المرحلة محصورة في الاختيار (١). ملفات النجوم والصلاة وبحر العرب والإشعارات والتكبير والتحميل محفوظة دون تغيير؛ يثبت اختبار البصمات ذلك للملفات الأصلية المتاحة.

## المعاينة وحدودها

- خدمة معاينة مستقلة `hada-ui-data-fixes-preview` بلا أسرار ولا جدولة ولا قاعدة بيانات.
- تقرأ من خدمة الموقع القائمة عبر اتصال داخلي في خدمة المعاينة فقط. لا تغيير لإعدادات خدمة الإنتاج. يسمح غلاف المعاينة بثلاثة مسارات بيانات عامة محددة وملفات صور عامة، وبطلبات GET/HEAD فقط؛ يمنع مسارات الإشعارات والكتابة وعامل الخدمة.
- تُعطل أزرار تفعيل الإشعارات في هذه المعاينة؛ إعدادات OneSignal الأصلية في الملفات محفوظة، ولا يستقبل هذا النطاق SDK الخاص بالنطاق المعتمد. لا حاجة لاشتراك جديد لاختبار هذه الإصلاحات.
- ملف `public/qa.html` وغلاف المعاينة أدوات اختبار فقط، ولا يدمجان ضمن واجهة الإنتاج عند اعتماد الإصلاحات.
- المعاينة ليست حزمة استعادة كاملة لخادم الإنتاج. نقل الإصلاحات للإنتاج يتطلب أخذ نسخة سليمة من مصدره الحالي ودمج ملفات الواجهة المطلوبة فقط، ثم موافقة مستقلة.

## التحقق

- `npm test`: نجح ١٠ اختبارات: الساعة الجارية والذروة المنتهية، القيم المفقودة، منتصف الليل ونظام ١٢ ساعة، فشل الاتصال والتعافي، مسح البيانات المنتهية، التحديث مع مرور الدقيقة، حصر نطاق التغييرات، ومنع الكتابة وتمرير بيانات الاعتماد في المعاينة.
- `npm run build`: بناء ١٩ ملف واجهة مع بصمات في `dist/manifest.json`.
- متصفح حقيقي: وصلت بيانات الطقس، وظهرت بطاقة المطر بتاريخ الجمعة ٢٣ أكتوبر وفترة ٣–٤ م وقت الفحص؛ هذه نتيجة اختبار وقتية وليست نشرة ثابتة. ظهرت صياغة التنبيهات الصحيحة مع رد مصدر حقيقي.
- تحققت الرياح والخريطة وتكبيرها بعد التعديل؛ نُفّذ اختبار تنزيل الخريطة على النسخة الأساسية في تقرير المراجعة السابق، ولم تُغير آليته هنا.
- فحص إطار هاتف بعرض ٣٩٠ بكسل: العرض الداخلي وعرض التمرير متساويان ٣٧٥ بكسل، دون تمدد أفقي للصفحة. هذا ليس هاتف سامر الفعلي.
- Windy أظهر خطأ توافق للأقمار في المتصفح السحابي؛ ليس جزءًا من هذه الإصلاحات، ولا ندّعي إصلاحه.

## التشغيل وإعادة البناء

داخل هذا المجلد: `npm test` ثم `npm run build`. لا تنزيل اعتمادات مطلوب؛ الأدوات تستخدم Node القياسي. إعداد المعاينة في `wrangler.jsonc`، ولا يتضمن أي route للموقع الرسمي. تاريخ التوافق ١٨ أكتوبر لأن منصة Cloudflare تعتمد يوم UTC وقت النشر، بينما تاريخ اليمن كان ١٩ أكتوبر.

قبل أي نشر عام: راجع الاختلافات المحدودة في `public/live-weather.js` و`public/hazard-alerts.js`، وأضف rain-period.js وrain-period.css وإشارتَي تحميلهما إلى HTML الحالي المطابق، دون استبدال مصدر العامل أو خدماته. `baseline-manifest.json` يوثق أصل الملفات ويحمي من الكتابة فوق نسخة أحدث بلا مراجعة.
